# 字體選擇理由與未驗證的字體規則

- 狀態：Hypothesis
- 舊規格出處：`docs/spec.md` 舊 §3.1；舊 §3.3 的兩條非編碼規則（見下方假設第 2、3 點）
- 假設：
  1. 主字體用 Noto Sans（多語言覆蓋完整、人文無襯線風格與流體動效方向一致），等寬字體用 Noto Sans Mono（與主字體同族，視覺一致性高）。
  2. 不使用 font-weight 100–300（在深色背景上過細，難以閱讀）。
  3. 最小可用字體尺寸：`10px`（僅限極端場景，例如 chart axis label）。
- 輸入：原規格 3.1 表格（理由欄位原文寫明「個人偏好」——唯一一條在規格裡直接承認理由是主觀偏好、非實驗證據的規則）；原規格 3.3 的後兩條規則。
- 狀態矩陣：尚未比較不同字體家族在實際消費端語言、密度、可讀性下的差異；假設 2、3 也沒有對應的渲染或可讀性測試。
- 壓力測試／情境：尚無記錄。
- 證據：字體家族與尺寸比例 token 已產出並被 pipeline 消費（E3：`palladio/pipeline/config.js`），但這只證明字體被實際使用，不證明字體選擇或假設 2、3 本身已被驗證。假設 2、3 目前沒有對應的 token 或驗證器，純粹是敘述性文字（不像 letter-spacing 值已編碼於 `palladio/tokens/semantic/typography.json`，那條已保留在 `docs/spec.md` §3.2 作為已升格契約）。
- 使用者裁決：尚未裁決。
- 結論：維持 Hypothesis。假設 2、3 爭議性低（字重可讀性、極端字級限制屬常見排版慣例），預期較容易升格，但在補上驗證證據或使用者確認前仍應誠實標記為未驗證，不得因為「看起來合理」就跳過裁決步驟。
